    * `lode.yml` è un workflow generico e riusabile che al `push` installa LODE e lo chiama per la generazione della documentazione in `docs/current/`

      * genera una release su GitHub sempre usando il valore in `owl:versionInfo`

* Ho centralizzato lo script di unit testing `test_ontology.py` in `sparontologies.github.io`, aggiungendo anche il rispettivo workflow `validation.yml` che lo fa funzionare, e ho modificato il workflow `validation.yml` specifico di ogni ontologia in un caller file:

```
name: Ontology Validation

on:
  push:
    branches: [ master ]
  pull_request:
    branches: [ master ]

jobs:
  validate:
    uses: SPAROntologies/sparontologies.github.io/.github/workflows/validation.yml@master
```

In `sparontologies.github.io` ho aggiunto `test_ontology.py` nella cartella `scripts/` e `validation.yml` in `./github/workflows/`:

```
name: Ontology Validation

on:
  workflow_call:

jobs:
  validate:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout ontology repository
        uses: actions/checkout@v4

      - name: Checkout validation tools
        uses: actions/checkout@v4
        with:
          repository: SPAROntologies/sparontologies.github.io
          path: .tools
          sparse-checkout: scripts/test_ontology.py
          sparse-checkout-cone-mode: false

      - name: Install uv and Python
        uses: astral-sh/setup-uv@v3
        with:
          version: "latest"

      - name: Run ontology tests
        run: >-
          uvx --python 3.13 --with rdflib --with owlrl --with requests --with codespell pytest
          .tools/scripts/test_ontology.py -p no:cacheprovider -rs --junitxml=validation_report.xml
        continue-on-error: true
```

Ho aggiunto in `test_ontology.py` un ulteriore check che si appoggia sul [web service di OOPS!](https://oops.linkeddata.es/webservice.html) per fare pitfall scanning. Solo quelli taggati come `[Critical]` sono considerati bloccanti.

Una run locale (e.g., per testing) diventa:
